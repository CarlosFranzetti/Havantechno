## 14:58 ET (19:58 UTC): design decisions (before code)

1. **One new global, `ImportView`** (`app/ui/import-view.js`, `import-view.css`) holds all four pieces so the System Editor and `app.js` change by a few lines each:
   - `ImportView.importTrack(host, {shell, toast, onDone})`: the import flow dialog.
   - `ImportView.mount(el, host, {onClose})` -> `{el, update(), refresh(), dispose()}`: the report view.
   - `ImportView.abControl(host, {toast})` -> `{el, update(), toggle()}`: the A/B group in the transport.
   - `ImportView.lane(host)` -> `{el, update(frac), dispose()}`: the reference lane band, built with the System Editor's own band classes (`se-band`, `se-bandl`, `se-area`, `se-ph`) so it lines up with the ruler columns.
   - `ImportView.availability(host)`: which frozen calls exist, each with a reason when missing (shared by every control so the reasons read the same everywhere).
2. **Import flow, three steps in one dialog** (`role="dialog"`, focus trapped to the dialog's controls, Esc = cancel): (1) pick the audio (`Project.pickAudio`); (2) stems: in Electron with `HavantechnoShell.separate` the dialog offers "Separate (HT-Demucs)" or "Analyse the mix", runs `separate(path)` and shows `onSeparateProgress` lines; in the browser it offers a drop zone and a "Pick stem files…" button (names map to drums/bass/other/vocals by file name, an unknown name keeps its file name) or "Skip: analyse the mix"; (3) `Project.importTrack({file, stems, shell, host, onProgress})` with a six-stage list (decode, separate, tempo, analyse, build, save), each stage marked waiting / running (done/total and note) / done, plus an overall bar.
3. **Cancel leaves the project untouched.** The frozen interface has no cancel, so: before the import starts I deep-copy `host.document()` (plain JSON). Cancel marks the run cancelled, passes an `AbortSignal` in the options (`signal`, harmless if D1 ignores it), and makes `onProgress` throw a cancel error on its next call (stops D1's pipeline if it calls onProgress between stages). When the promise settles, if the host's document is no longer the snapshot, `host.loadDocument(snapshot)` restores it. Stated limit: a project file `importTrack` already saved stays on disk; the dialog says so. **To D1:** please honour `opts.signal` (stop between stages) and let a throw from `onProgress` reject the promise.
4. **Report view = a panel over the view area** (absolute in `#view`, toolbar stays live so the owner can A/B while changing recreations). Header: source name, duration, sample rate, tempo with its confidence, separator. Then the report's own `unverified` notes in full (never truncated). Then one row per element: name and stem/band; each decision as a chip with label, value, **confidence word** and a **three-pip weight** (high: 3 filled pips, solid border, full text; medium: 2 pips, solid border; low: 1 pip, dashed border, dim italic text with a trailing "?"; none: hollow pips, "no call"), so a low call never looks like a fact even without colour; evidence and alternatives in a native `<details>` (keyboard works); what was loaded (track name and its instrument, or "nothing loaded"); a `<select>` to change the recreation with optgroups: suggested, drum machine voices (`Drums.types()`), classic synths (`Classics.types()`), engine synths (`Synths.types()`), sampler, none. A change calls `host.applyRecreation(id, recreation|null)` (the host makes it one undo step); `false` reverts the select and shows why. The element's own `unverified` notes (Analysis carries them per element) are shown in full under its row.
5. **A/B in the transport**, replacing the disabled placeholder: a two-button segment `Song | Ref` with `aria-pressed` on the side heard, key **A** (free: the app binds Space, Tab, V and Ctrl/Cmd S O Z Y 1 2; Windows binds Ctrl/Cmd+W; no view binds a plain letter); `Match` button (calls `host.matchLevel({section})` on the looped section, else the section under the playhead; the readout then shows `ref +2.1 dB · song −9.4 / ref −11.5 LUFS (mainA)`, or "could not measure"); a reference gain field in dB (−24..+12, written as linear through `setReferenceParam('gain')`). When there is no reference the controls use `aria-disabled` (still focusable), their title says why, and activating them (click or A) shows the reason in a toast: a reason that can be seen, not only hovered.
6. **Reference lane** above the track rows (after the TRACKS header): left column "REFERENCE", file name, gain in dB, "loading" or "missing" state; right column a canvas the width of the ruler area drawn at `devicePixelRatio`. Mapping: bar b (0..total bars of the arrangement) -> reference time `offset + b * 240 / bpm` (4/4, sixteen steps a bar, `host.bpm()`); per-column min/max from a peak cache built once per buffer (256-frame blocks), so a redraw is cheap; time outside the file is left empty. Redraw only when width, dpr, bpm, offset, buffer or gain change. Playhead: an `se-ph` line set with the same fraction as the ruler's in the System Editor's `update()`. When the reference is heard (A/B on Ref) the waveform is drawn in `--fg`, else in `--dim`. Limit: a tempo change inside the song (a section `set` of bpm) is not followed; the lane uses one bpm.
7. **Toolbar**: `Import…` next to Save/Open and `Report` (disabled, with the reason in its title, until `host.analysis()` returns a report). The System Editor's "+ track" menu gets "Import track…" (calls `App.importTrack` when present, else `ImportView.importTrack`).
8. **Undo**: every document change goes through one host call (`setReference`, `applyRecreation`, `importTrack`), each one undo step by contract; gain and A/B are live session/document values with no extra undo entries from the UI.
