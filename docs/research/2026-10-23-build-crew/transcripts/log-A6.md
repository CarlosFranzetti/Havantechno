## Decisions

1. **index.html** loads the contract order, with `engine/project.js` right after `engine/host.js` (the contract list omits it). `#frame`, `#view`, `#windows`, `#start-overlay` (`#start-audio`, `#start-status`). Frame and window CSS is injected by `app.js` and `windows.js` (classes `ap-*` and `wn-*`; A2's `hv-*` names are not reused, to avoid collisions).
2. **Views mount before Start.** A1's Host works without audio, so the System Editor shows behind the overlay. Start calls `host.start()`; if it resolves `false` the overlay offers "Continue without audio". After Start the autosave is read (`Project.restoreAsync`, else `restore`) and loaded with `host.loadDocument`; autosave stays off until that attempt is done, and `'document'` events with `reason: 'start'` never schedule an autosave (otherwise the default song could overwrite the saved one).
3. **Autosave** is debounced 1.5 s on `'document'` events and on `'param'` events with `source: 'ui'` (knob moves are stored in the document by Host but do not emit `'document'`). It is flushed on `pagehide` and when the tab is hidden.
4. **Keys** (`App.handleKey`, one function used by the page and by device windows): Space play/pause (always, except in text fields and selects; keyup is swallowed so a focused button does not also click), Tab switch System/Step (not in text fields; Shift+Tab keeps focus movement), Alt+1/2 and Ctrl/Cmd+1/2 pick a view (F-O1's alternative to Tab), V hide/show device windows, Ctrl/Cmd+S save, +O open, +Z undo, +Shift+Z or +Y redo (not inside text fields). Esc and Ctrl/Cmd+W close a focused device window (windows.js). Accessibility cost: Tab is taken for the view switch as the CONTRACT says; keyboard users move focus with Shift+Tab or Alt+1/2 until the owner decides.
5. **Control bar**: wordmark (brand pink), view switch (System Editor | Step View | Mixer, disabled), rewind/Play/Stop (Play is pink while playing; its `aria-label` is "Play" or "Pause"), BPM and swing inputs (`host.setParam`), `bar · step · section` from `transport.pos()`, A/B disabled, master meter (`Widgets.meter`, fed by `host.meter('master').level`), "Re-enable arranged (n)", undo/redo glyph buttons, Save/Open (`Project`), Export WAV, and a "Windows (n)" menu (hide/show all, Tile, Cascade, Close all, Link Off/Single/Multi). Export renders the whole song with `host.render({})` + `host.wav`, then downloads (web) or `shell.saveFile` (Electron). The bar fits one row at 1440 px and wraps below that.
6. **The ruler is not in the frame.** A4 and A5 draw their own section ruler inside their views, so `app.js` has none. Section sharing: on mount of a view, and on each host `'section'` event, `app.js` calls `view.selectSection(name)` when the view has it (A5's request relayed by the coordinator). Consequence: the Step View follows the playhead while playing. If that is unwanted while editing, change the `'section'` handler in `bootMain`.
7. **View switch** disposes the old view and mounts the new one, carrying the selected track (`Windows.selectedTrack()`, fed by `Windows.onSelect`) and the section under the playhead. The chosen view is remembered in localStorage (`hv.view`). `?song=v2` opens `Song.documentV2()` (A1's open question: the default stays the baseline).
8. **Windows (web).** In-page panels in `#windows`. One window per device id. Header: family glyph, `name · family` (+ `on <track>` for inserts), preset menu (disabled placeholder), Mute (instrument, channel: `host.mute` / `getParam('<track>.mute')`) or Bypass (anything with `ref.bypass`), Editor | Controls, `Link: Off|Single|Multi` (cycles the global mode), pin, close. Body: `Faces.render(dev,'window',host)`; Controls: `Faces.fallback(dev,'window',host)`. Footer: control under pointer or focus (label and value from ARIA attributes), section name and held count, key hint. Drag by the header (pointer capture), resize by the east, south and corner handles, Alt+arrows move and Alt+Shift+arrows resize from the header. Rect and view stored per device id in localStorage `hv.win.<id>`, clamped onto the viewport on open and on browser resize. Default size is the face's natural size. Tile and Cascade persist the new rects. `face.update()` runs every frame; `face.resize(w, h)` is called from a ResizeObserver on the body and after each rebuild (A3's note). The face is rebuilt when the device's `ref` changes (checked on `'document'` events and every 45 frames).
9. **Link semantics.** Off: each open makes its own window. Single (default): one linked window, the most recently used unpinned one; opening a device that has no window retargets it; selection follows. Multi: every unpinned window follows by role. Pin freezes a window, and the next open creates a new linked one. A device never has two windows (opening focuses). `Windows.onSelect(id)`: a track-level id (the instrument device) makes followers show their own role on that track (same insert type, channel, sidechain), falling back to the instrument in Single mode; any other device id is shown as is. V toggles hide-all and a hidden window keeps its state. The caps and warnings F-O1 mentions (soft warning at 8) are not built.
10. **Electron.** `main.js` serves `app/` through the standard secure scheme `havantechno://app/` (stable origin: localStorage persists, device windows are same-origin with the main window, so `window.opener` works; `file://` would not allow that). `HAVANTECHNO_URL=http://localhost:8000/app/index.html npm start` loads the dev server instead. Device windows: the renderer asks `HavantechnoShell.openDeviceWindow(id)`; the main process runs `window.open` in the main window's world (so the child has `window.opener`), and `setWindowOpenHandler` allows only same-origin `?device=` URLs, sets `parent: mainWin` and the remembered bounds (`<userData>/window-state.json`, clamped onto a display that still exists). IPC: `openFile({filters, binary}) -> {name, path, text|bytes} | null`, `saveFile({name, text|data, filters}) -> {name, path} | null` (matches `project.js`), `appDataPath`, `readAppData(name)`, `writeAppData(name, text)` (names restricted to `[A-Za-z0-9._-]`), `openDeviceWindow`, `closeDeviceWindow`, `setDeviceWindowsVisible`, `arrangeDeviceWindows('tile'|'cascade')`, `listDeviceWindows`, plus `onDeviceWindowClosed(fn)`. Menu has no Undo/Redo roles so Cmd/Ctrl+Z reaches the page. `contextIsolation` on, `nodeIntegration` off, sandboxed preload.
11. **Device window page** (`?device=<id>`): `app.js` builds a host-shaped object over `window.opener.HavantechnoBridge` (`setParam, getParam, hold, release, releaseAll, heldCount, isHeld, device, devices, meter, sections, tracks, sends, bpm, swing, mute, solo, transportPos, playing, on, off, key, select`) and calls `Windows.embed`, which draws the same header/body/footer filling the page. The child registers with the opener (`Windows.registerChild`), so Link, Pin and selection-follow work across OS windows; Space, Tab, V and the Ctrl/Cmd keys are forwarded to the main window; listeners are removed on `pagehide`; the child closes itself if the main window is gone.
12. **package.json**: name `havantechno`, `main: shell/main.js`, scripts `start` (`electron .`) and `web` (`node ../tools/serve.js`), `electron` pinned to `45.0.0` (`npm view electron@45.0.0 version` printed `45.0.0`; it was the latest listed). `app/node_modules/` is already in `.gitignore`.
13. **tools/serve.js**: static server for the repo root, COOP `same-origin` and COEP `require-corp` (plus CORP same-origin, no-store), port from argv, `PORT` or 8000, prints `App: http://localhost:<port>/app/index.html`. Decodes URLs (the archived folder has spaces), refuses paths outside the root (403), 404 otherwise.

## Answers to messages

- **From A6 to A1:** `window.HavantechnoApp = {host, app}` is exposed; `host.mute` and `getParam('<track>.mute')` are used for Mute; `host.isHeld` and `heldCount` for the bar and bridge. Shell API matches `project.js`. Default song stays `Song.document()`; `?song=v2` opens V2.
- **From A6 to A10:** `#start-audio`, `#frame` with a button of `aria-label="Play"` (becomes "Pause" while playing), `data-view="system|step"` on the mounted view's wrapper, windows are children of `#windows`. The check's "device title" step fails because it first switches to the Step View and then looks for `.se-dtitle[title^="Double-click"]`, which only the System Editor has (and which A4 draws only as a fallback; with the real Faces, the double-click target is the face's `.hv-head`). Fix in the check: open the window before pressing Tab, or look for `.hv-head`.
- **From A6 to A4:** a double-click on a face head (`.hv-head`) opens the window with the real `Windows.open` (verified in Chromium; the window for `track:kick` appeared). `Windows.onSelect('track:<name>')` is the right call for a track selection.
- **From A6 to A5:** `view.selectSection(name)` is called on mount and on every host `'section'` event. The frame has no shared ruler.
- **From A6 to A3:** `face.update()` each frame and `face.resize(w, h)` on window resize are wired. Note: in the `window` density the face draws its own head (glyph and name), which repeats the window title bar; your call whether to drop it at that density.

## Known problems and not done

- **Full-song export is slow in this sandbox.** `host.render({from:0,to:8})` took 1.7 s but a 48-bar render ran more than 100 s, and the full 200-bar export from the button did not finish in 180 s in headless Chromium. That is in `Sequencer.render` or the processors (A1/A8/A9), not the frame; the button, WAV encoding and download are verified only with a 4-bar render.
- Mixer drawer, A/B, preset menus: placeholders (disabled).
- No screenset memory, no cap on windows, no "open window when an insert is added" preference.
- Position readout is a `role=timer` that updates every step; screen readers may announce it often.
- `app/index.html` loads `engine/project.js`, which the contract's load order does not list; the coordinator may want to add it to CONTRACT.md.
