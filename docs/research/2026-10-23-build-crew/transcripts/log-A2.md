## Decisions

1. **Control element.** Knob and slider are one `<div role="slider" tabindex="0">` with aria-valuemin/max/now, aria-valuetext (unit, plus ", held" / ", ramping" / ", set by arrangement" so the shape-only markers are also spoken), aria-label, aria-orientation. I did not use the hidden `<input type=range>` of F-S2: the CONTRACT asks for `role="slider"` and a hand-written key table is short. Toggle is a native `<button aria-pressed>`, select a native `<select>` (option values keep their original type).
2. **Gesture grammar (F-S5 round 2 table).** Vertical drag, 200 px for the full range in position space (log params drag in log space); Shift = x0.1. Sliders drag along their axis (h: horizontal, v: vertical, track length is the travel); a press on the track jumps there unless Shift is down. Double-click or touch double-tap (own 320 ms timer) = home value; Shift+double-click, Alt-click, Shift+Delete = factory value. Delete/Backspace = home. Enter (or 550 ms touch long-press) opens a typed-value field (accepts "2.4k"). Arrows 1% of range, Shift+arrow 0.1%, PageUp/Down 10%, Home/End min/max. With a `step` option, arrows move one step, PageUp ten. Value tooltip while dragging and 800 ms after.
3. **Wheel acts only on the focused control** (a click focuses it). Reason: faces sit in scrolling panels and wheel-over-hover would hijack page scroll. Not verified in a real browser beyond the fake-DOM test; easy to flip if the coordinator wants hover.
4. **Home / factory.** Options `home` (number or function) and `factory`; both default to the initial value. `setHome(v|fn)`, `setFactory(v)` exist so A3's `update()` can point home at the section's arranged value and factory at `spec.value`.
5. **Hold protocol.** `onHold()` fires once per gesture, on the first actual value change (not on a bare click), for drag, wheel, keys, reset and typed value. `onInput(v)` on every user change. `set(v)` never calls callbacks and is ignored while the control is being dragged, so A3 can call it every frame. `onRelease()` fires when the user clicks the open ring marker of a held control (F-S5: "clicking the individual dot clears one"). The widget never sets its own state: A3's `update()` must call `setState` from host data.
6. **Markers (shapes, neutral `--fg` ink, no family hue).** Small svg at the top-left corner of every knob and slider: `'set'` filled dot, `'ramp'` dot with a slant plus a ghost arc behind the knob (`setRamp(from, to)` in value units draws the arrangement's from/to arc; without it no ghost arc), `'held'` open ring plus the value arc turns dashed `--fg`. `setStock(v)` draws the "differs from stock" tick on the arc (F-S5 round 2); `null` hides it. `data-state="set|ramp|held|none"` is on the element for CSS.
7. **Log scale** only when `log: true` and `min > 0`. Bipolar knobs (arc from the centre) automatic when `min < 0 < max`, or `bipolar` option. `Widgets.scale(min, max, log, step, unit, fmt)` returns `{toPos, fromPos, snap, format}` for A3 if it needs the same mapping.
8. **Sizes.** knob svg 24 / 36 / 52 / 64 px for chip / strip / face / window; sliders 24 / 24 / 28 / 44 px thick, length 56 / 80 / 112 / 160 (`length` option overrides); `.hv-ctl` has `min-width/height: 24px`, 44 px at `data-size="window"`. Chip hides label and value (tooltip only), strip hides the value readout. Step cells are 24 px tall, flexible width with a 14 px minimum (width is below 24 in a 384 px row; the spacing exemption of WCAG 2.5.8 is my reading, not verified).
9. **Steps.** Cells accept `null`, boolean, number (velocity) or SongDoc cell `{vel, acc,...}`. Level 1 soft (vel <= 0.6), 2 on, 3 accent (acc or vel >= 0.95), drawn as three opacity steps of `--fam-ink` (or `ink` passed in, set as `--step-ink`). Toggle comes from the native `click` (so Enter/Space work): `onToggle(i, {shift, alt})`. Vertical drag on a lit cell: `onDrag(i, vel)` (60 px = full range, steps of 0.05; click after a drag is swallowed). ArrowUp/Down on a lit cell does the same by 0.15. Left/Right/Home/End move a roving tabindex. Extra: `setCursor(i)` marks the playhead cell (`data-cursor`, `--on` outline).
10. **Canvas.** `meter` maps linear peak to a -60..0 dB scale with instant attack and smoothed fall, peak tick held 40 calls; green `--on`, red `--arm` above about -1 dB (state tokens, not family hue). It skips repainting when nothing moved at 1/400 resolution. `curve.draw(ctx, w, h, colors)` gets a fourth argument (resolved `bg panel raised line fg dim on arm solo ink famDim wash`), caches computed style per nearest `data-fam` and re-reads every 120 redraws; `Widgets.refreshTheme()` forces a re-read. `curve` fills the `wash` ground first and survives a throwing `draw`. `grMeter.set(dB)` takes negative or positive dB or null (the engine's `reduction` is negative) and hangs from the right end; `correlation.set(-1..1)` draws from the centre, red when negative. Canvas is HiDPI-scaled. No canvas context (fake env): all of them no-op, no throw.
11. **No CSS injected by widgets.js**; everything is in `theme.css`.

## Wave 2: gesture phases (A11 finding S1)

Change in `app/ui/widgets.js` only (plus `tools/widgets-check.js`); `theme.css` untouched.
- **`steps` `onDrag(i, vel, phase)`.** `'start'` on pointerdown on a lit cell (carries the current velocity); `'move'` only when the quantised velocity (steps of 0.05) changes, so a 40 px drag is a handful of calls instead of one per pixel; `'end'` on pointerup or pointercancel with the final velocity, always paired with a `'start'`. ArrowUp/Down on a lit cell is a single `'end'`. Empty cells emit nothing. A bare click on a lit cell gives `start, end` with the same velocity and then `onToggle` from the click, so **A4 should write on `'end'` only if the velocity differs from `'start'`'s**, preview on `'move'`, and commit once.
- **`knob` / `slider`.** `onInput(v, phase)` keeps working for callers that ignore the phase: phase is `'move'` during a drag or a wheel burst and `'end'` for a discrete change (key, reset, typed value). `onInput` never gets `'start'`, because A3's faces write on every `onInput` and a pointerdown alone must not write. The new optional `onGesture(phase, v)` carries the bracket: `'start'` on pointerdown (or first wheel tick), `'end'` on pointerup, pointercancel, long-press-to-type, or wheel idle (300 ms); a discrete change is a single `'end'`. `onHold` is unchanged (once per gesture, on the first real change).
- `call()` now forwards any number of arguments.
