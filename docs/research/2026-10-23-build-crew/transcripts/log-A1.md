## Decisions

1. **A dry engine before audio.** `Host.create(opts)` builds the song at once on a context-less `Sequencer` (`Sequencer.create(null)`), so `devices()`, `getParam`, `sections()`, the editor and the events all work before the Start gate and in Node. `start()` creates the AudioContext and rebuilds the same document live. Device `ref`s therefore change on `start()`, `loadDocument()` and a structural `commit()`: every rebuild emits `'document'` with `{reason: 'start'|'load'|'commit', rebuilt: true}`; UI code that caches `ref` should refetch `devices()` on that event.
2. **Commit is incremental when it can be.** `commit()` compares a structural key (everything in the document except `tracks[].variants` and `sections`, plus `progression`) with the last build. Step edits, variant forks, `setPlay`, section `set`/`ramp`/`fx` and progression edits are applied to the running sequencer in place (`tr.variants` re-parsed, `seq.setArrangement(doc.sections)`, `seq.progression`), with no rebuild and no audible gap. Anything else (track params, chains, sends, bpm, tracks added) disposes and rebuilds, then restores the step position, play state, loop section, held paths, mute and solo. `'document'` carries `{reason:'commit', rebuilt: bool}`.
3. **Knob values are written into the document.** `host.setParam(path, v)` applies the value live and, when the path maps to the document, stores it there too (`track.params`, `track.gain`/`pan`, `track.chain[i]`, `track.sidechain`, `track.sends`, `doc.sends[name]`, `doc.bpm`/`swing`, and a new optional `doc.master[unit][param]` that the Host applies after `Song.build`). Without this a rebuild would undo the user's tweaks and Save would lose them. No undo snapshot is taken for a knob move (that would flood the undo stack); an undo of a later step edit restores the snapshot, which can put back an older knob value. Mute is session state and is not stored.
4. **`'param'` events.** `source: 'ui'` for `host.setParam`; `source: 'arrangement'` for section `set` and `ramp` writes. Those are scheduled ahead by the lookahead, so while playing the Host queues them on the sequencer's event queue at their audio time (the same queue that times `'step'` and `'section'`); when stopped they fire at once.
5. **Meters are lazy.** `meter(id)` creates its AnalyserNode (fftSize 1024, about one frame at 48 kHz) on the device output the first time it is asked, so only metered devices cost anything. Level = peak of `|x|` over the buffer, clamped to 0..1 (`peak` carries the raw value). `reduction`: `p.node.reduction` (number or legacy AudioParam) for compressor and limiter; for the sidechain the dip of its gain in dB (`20·log10(gain)`), which the face needs as well. `correlation` for `'master'` and every `master:<unit>` through a 2-way splitter and two analysers; silence reads 0. Without a context `meter()` returns `{level: 0, peak: 0, reduction: null, correlation: null}`. `meter('master')` meters the final output (`seq.out`) even though there is no device with that id.
6. Additions beyond the contract (all optional for callers): `host.mute(track, b)`, `host.solo(track, b)` (the rows need M and S; `setParam('<track>.mute', b)` is routed to the same code), `host.dispose()`, `host.started()`, `host.context()` (null before start; used by tools only), `transport.setLoop`-free: `loop(ref|null)`. The channel device's `spec` is the channel spec plus one entry per send, keyed `'send.<name>'` ({min 0, max 1.5}), so `pathPrefix + '.' + param` gives `kick.send.delay`, which `setParam` and `getParam` both accept.
7. `render({from, to, sampleRate, tail})`: `from`/`to` are bars or section names (`to` as a name means the end of that section). The render builds a copy of the current document (knob values included) and applies the current mute and solo state.
8. **Editor additions (answer to A5).** `songdoc.js` is unowned this wave, so the three operations A5 asked for live on the editor the Host hands out (`host.editor()`), added in `host.js` by `extendEditor`, each with one undo snapshot like the built-in operations: `ed.group(fn)` (several operations, one undo step; returns `fn`'s result), `ed.setFx(section, index|null, patch|null)` (null index adds a hit `{bar, step, track, bars, vel}`, null patch removes it, else merges; returns the index or -1), `ed.setVariantBars(track, variant, bars, fill)` (1..64 bars; `fill` `'repeat'` (default) loops the existing bars into the new ones, `'empty'` leaves rests; shrinking truncates). They should move into `songdoc.js` when someone owns it; the Host keeps the same names.
9. **Project file format.** `{app: 'havantechno', format: 1, savedAt, song: <SongDoc v1>}`; `parse` also accepts a bare SongDoc (`v: 1`) and rejects other files, other formats and bad JSON with an Error. Web: Save downloads `<name>.havantechno.json` through a Blob link; Open uses a hidden `<input type=file>` (resolves null on the `cancel` event; browsers without that event leave the promise pending on cancel). Electron (only when `HavantechnoShell` exists): `saveFile({name, text, filters})` and `openFile({filters})`, both resolving null on cancel, as A6's `preload.js` and `main.js` now define them. Autosave writes localStorage synchronously (so `restore()` stays synchronous as the contract says, in Electron too) and mirrors to `shell.writeAppData('autosave.havantechno.json', text)` when present; `Project.restoreAsync()` reads `shell.readAppData` first. Extras: `Project.savedAt(json)`, `clearAutosave()`, `appDataPath()`, `fileName(name)`.

## Decisions

1. **Where samplers get `getBuffer`.** The sequencer does not change, so the Host builds sampler instruments itself: before `Song.build` it makes a shallow copy of the document whose sampler tracks carry `inst: Synths.create(ctx, 'sampler', params + {getBuffer})` (`addTrack` accepts a ready instrument). Non-sampler tracks are the document's own objects, as before. The same path serves `render()`, so exports play samples. `getBuffer(id)` reads the Host's table at trigger time; when a file finishes loading, the Host re-sets `buffer` on the samplers that use it (no rebuild).
2. **Decoding before Start.** `loadAudio` decodes with the live context after `start()`, else `opts.context`, else an `OfflineAudioContext(2, 1, 44100)` (no gesture needed), else it rejects with "no AudioContext". So a restored project's samples load behind the Start overlay. Note: decoding resamples to the decoder's rate; `doc.audio[id].sampleRate` is the decoded buffer's rate, not the file's, and a buffer decoded at 44.1 kHz plays in a 48 kHz context through the source node's resampling.
3. **Ids and relinking.** The id is the file name without its extension, lower case, `[a-z0-9_]`, at most 40 characters, made unique with `_2`, `_3`. A load whose file name matches a missing entry takes that entry's id (re-adding a file on the web relinks it). `src` is the URL, the shell path (`{name, path, bytes}` from `openFile({binary: true})`, or `HavantechnoShell.pathForFile(file)` / `file.path` when present), else the file name.
4. **Reloading.** `host.reloadAudio({shell, base})` runs after `Host.create`, `loadDocument(doc, {shell, base})` and `start()` whenever an entry has no buffer. URLs (`http(s):`, `blob:`, `data:`) go through `fetch`; other `src` values go through `HavantechnoShell.readFile(src, {base})` when the shell exists; anything else (a bare file name on the web) is missing, without a fetch (a 404 would fail the browser check). It never rejects; each missing file emits `'audio' {id, status: 'missing'}` and its track plays silent. `loadDocument` keeps decoded buffers whose id, name and src match the new document, so restoring the same project does not decode again.
5. **The document.** `songdoc.js`: `doc.audio` is normalised on save and load to `{name, src, duration, sampleRate, channels}` per id (anything else, bytes included, is dropped; a bad map loads as `{}`); a document without samples saves no `audio` key, so existing files and the schedule-equivalence checks are unchanged. A track with `type: 'sampler'` or `inst: 'sampler'` gets both, and `params.buffer` (default `''`). New editor operations `ed.addTrack(def, index)` (legacy strings or variants, one undo step) and `ed.removeTrack(name)` (also removes the track from section `play`, `fx`, `duck` lists and section `set`/`ramp` paths). `fromLegacy`/`toLegacy` carry `audio`.
6. **Families.** `sampler` is `drums` by default; a document track's `family` field (one of the eight) overrides the family of its instrument device, so a sampled vocal can sit in `keys` or `fx`.
7. **Extras for the UI.** `host.buffer(id)` (the AudioBuffer for A3's waveform hero), `host.addSampler(source, {name, family, pattern})` (loads, adds a track playing `'x...............'` unless told otherwise, commits; for A4/A6's drop target), `Project.open({shell, host})` (loads into the host with the project folder as `base` and resolves after the reload).
8. **CONTRACT.md.** Host section: the wave-1 extras and the audio calls, as the coordinator asked. Sampler section (allowed in the same pass by the coordinator's part-2 message, item 7): no own `gain` (the common instrument `level`), and the pitch offset comes from `ev.midi` (the sequencer never sends `ev.note`), semitones = `ev.midi − 48`.
