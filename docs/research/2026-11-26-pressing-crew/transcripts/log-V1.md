Facts that shape the design:
- `Sequencer.render` starts the song at t0 = 0.05 s in its buffer and renders span + tail + 0.1 s. An export cuts exactly `round(0.05 * sr)` frames off the front and keeps `round((span + tail) * sr)` frames, so its length is exact to the sample.
- The instrument registry is `Synths.create` in synths.js (not mine) and has no hook. The Host already builds sampler instruments itself in `buildSong` and hands them to `Song.build` as `def.inst`; audio tracks are built the same way.
- `Math.random` is used by `Kit.noise` (one noise buffer per context), `Kit.impulse`, drums.js (spread) and synths.js (noise start offset). Two renders of the same song therefore differ in every noise voice. The worklet uses its own seeded LCG.
- The master chain's input is a plain gain (unity) in front of eq, hp, lp, glue, sat, limiter.
- Mute is a `setTargetAtTime` on the channel's mute gain from time 0 with tau 10 ms: a muted track leaks about e^-5 (-43 dB) at the first step of a render (t0 = 50 ms). The export does not use it (below).
- The shell's writeFile requires the parent folder to exist and has no way to make one.

Decisions:
1. **One render per file, one file at a time.** Each file (the mix, each stem) is one `Sequencer.render` on its own OfflineAudioContext at the chosen rate, encoded at once, handed to `onFile`, and its AudioBuffer dropped before the next starts. `Project.exportAudio` writes or downloads each file in `onFile` and sets `bytes` to null, so only one file is ever held.
2. **Seeded randomness.** During each export render `Math.random` is replaced by a seeded generator (mulberry32, seed from the option `seed`, default 1) and restored when the render settles. Every render then draws the same numbers in the same order, so stems and the mix share the same noise. Exports are serialised so two never overlap. Limit, stated: anything else on the page drawing random numbers during an export (live playback's noise voices) shifts the stream; exact sums assume the transport is stopped.
3. **Stems rule.** A stem is a track after its own strip (instrument, inserts, sidechain, channel gain and pan) with the master chain bypassed (`master: false`, the default for stems) and its sends left out. Each send's return is its own stem file (`return-<send>`), holding the returns of the same set of tracks. So the files of one stem export sum to the mix of those tracks with the master off, which the checks measure. With `master: true` each stem goes through its own copy of the master chain; that sum is not the mix, and the residual is measured and stated. The mix keeps `master: true` by default.
4. **How a stem is isolated.** Every track of the song is still built and triggered (ducking and the random stream stay as in the mix), but the tracks outside the stem have their instrument output disconnected from their strip (no mute ramp, so no leak, and the renderer does not pull them). Dry stem: the track's send gains are disconnected. Return stem: every track's channel output goes only to its send gains, not to the master input. A send gain the arrangement creates later (setSend from a section `set`) gets the same rule through a wrapper on `seq.setSend`. Master off: the master chain's output is disconnected and its input goes straight to the output.
5. **Which tracks.** `what: 'stems'` = every track audible under the current mute and solo, plus the send returns; `what: [names]` = those tracks whatever their mute (named on purpose), plus the returns of those tracks; `'mix'` keeps mute and solo (silenced tracks disconnected as above), held values and bypass. A return stem that comes out silent is left out. `sends: false` leaves the returns out. The reference track is never in any render.
6. **WAV writers** in sequencer.js (`Sequencer.wav(buffer, {bitDepth, dither, seed})`): 16-bit PCM with TPDF dither (two uniform draws, plus or minus 1 LSB peak, no noise shaping; on by default for 16-bit, `dither: false` turns it off), 24-bit PCM (no dither by default), 32-bit IEEE float (format 3, an 18-byte fmt chunk and a fact chunk; values over 1 are kept). Scaling is x * 2^(n-1), rounded, clamped. `Sequencer.wav(buffer)` with no options is the old 16-bit writer, unchanged, so the existing Export WAV button and tools keep their bytes.
7. **Audio tracks** (new app/engine/audiotrack.js, global `AudioTrack`): an instrument object with an `onStep(absStep, t, seq)` method. The sequencer calls `onStep` for every track that has it at every scheduled step (one guarded line in `schedule`). A step that does not follow the previous one (play, jump, loop wrap, a render from mid-song, a throttled tab) fades the playing clips out over 4 ms at that step's time and starts every clip that covers it mid-clip at the matching file position; clips whose start falls in the step start at their exact time. Positions are `offset + (step - clipStartStep) * stepSec` at the current tempo. Not time-stretched: a clip plays at its file's own rate; if the song tempo is not the clip's, the clip keeps its own speed and drifts from the grid after its start, and a tempo change while a clip plays does not move it (it is re-placed at the next jump or wrap). Mute and solo are the track's channel strip. Clip edits are applied in place (no rebuild): the next step re-places the clips.
8. **Clip document:** `track = {name, type: 'audio', inst: 'audio', gain, pan, chain, sends, clips: [{audio, bar, offset, length, gain}]}`; bar is 0-based like `host.render`'s from (fractions allowed), offset and length in seconds of the file (length 0 = to the end of the file), gain linear. Editor operations in songdoc.js: `addClip`, `moveClip`, `trimClip`, `setClip`, `removeClip`, one undo step each, refused ones none.
9. **Audio options:** latency hint and sample rate rebuild the context (the transport stopped where it was, the document, held paths, mute and solo kept, the worklet module loaded on the new context before the rebuild, the reference nodes and meters remade); the output device goes through `setSinkId` when the context has it, else the call resolves false.
10. **Bundle:** Electron: a folder from `pickDirectory`; `project.havantechno.json` in it and every `doc.audio` file copied into `audio/` (copyFile from its absolute path, or a 32-bit float WAV of the decoded buffer when there is no readable path), with the bundle's document pointing at `audio/<file>`. `audio/` needs a folder made: `HavantechnoShell.makeDirectory` is feature-detected; without it the files go beside the document (said in the result). The live document is not changed. Web: the document alone through `Project.save`, files relinked by name when re-added.
