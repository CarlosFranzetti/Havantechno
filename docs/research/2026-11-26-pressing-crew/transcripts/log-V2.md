Read: CLAUDE.md, BRIEF.md (item 2, frozen interface), app/CONTRACT.md (Host, Widgets, Windows, System Editor, App), app/ui/app.js, system-editor.js, widgets.js, theme.css, import-view.js and its dialog, tools/import-view-check.js, tools/browser-check.js, the two screenshots. At this time host.js has none of V1's calls (exportAudio, addAudioTrack, audioOptions, setAudioOptions, outputDevices); every one is feature-detected.

**Views.** Four entries in the switcher: System Editor (the arrangement, unchanged), Step View (kept: it is an existing view and browser-check uses it), Mixer, Clips. Each new view is `XView.mount(el, host) -> {update, dispose, select?}` like the other two. app.js keeps one mounted view at a time; `hv.view` in localStorage remembers the last one.

**Keys.** Tab cycles System Editor -> Step View -> Mixer -> Clips -> System Editor (Tab from the System Editor still lands on the Step View, so browser-check's "Tab to Step View" row is unchanged). Ctrl/Cmd+1..4 and Alt+1..4 pick a view directly (1 System Editor, 2 Step View, 3 Mixer, 4 Clips; 1 and 2 were already there). Ctrl/Cmd+comma opens Settings. Ctrl/Cmd+Shift+E opens Export. Escape closes the dialogs.

**Mixer.** One strip per track from `host.tracks()`, grouped by family (drums, bass, keys, fx, then any other family), each: family rail and name, a button opening its device window (`Windows.open('track:<name>')`), pan knob (`<track>.pan`, -1..1, double-click centre), one knob per send (`<track>.send.<name>`, 0..1.5), M and S (`host.mute/solo`, session state, no undo entry, as the System Editor does), a vertical fader on the channel's `gain` (`<track>.gain`, linear 0..2 in the engine, shown in dB from -60 to +6; the bottom is -inf; double-click = 0 dB), a peak meter on the channel output (`host.meter('track:<name>:channel')`) with a held-peak readout in dB (click resets it). Undo: every fader/knob gesture calls `host.hold(path)` once (the Widgets `onHold`), which is the Host's one undo snapshot per gesture, the same path the faces use; the value is written with `host.setParam` (stored in the document). Returns: one strip per send (`host.sends()`): meter on `send:<name>`, a level fader on the unit's `mix` when its spec has one, bypass (`host.bypass`), open. Master: the master meter, the limiter's gain reduction (`host.meter('master:limiter').reduction`) and the glue compressor's, correlation, open buttons for the limiter. The engine has no master volume, so the strip says so instead of showing a fader that does nothing. The strip row scrolls horizontally inside the view (`overflow-x:auto` on the view's own box; the page never scrolls). Rebuilt on the Host's `document` event when the track list changes; values pulled every 4 frames when the control is not being dragged or focused.

**Clips.** Rows = tracks of `host.document()`, columns = `host.sections()` in order (the engine's sections are the scenes). Each cell shows the variant letter that track plays there, or an empty marker. Clicking a cell (or Enter/Space) opens a small menu of the track's variants plus "empty"; choosing one calls `host.editor().setPlay(section, track, letter|null)` (one snapshot = one undo entry) then `host.commit()`. Arrow keys move between cells (roving tabindex). A launch button per section header calls `host.transport.jump(name)`, `host.transport.loop(name)` and plays if stopped; launching the looped section again releases the loop. The section under the playhead and its cells are highlighted, the looped one marked. A visible note at the top says: "The arrangement's sections seen as a grid: each cell is the pattern variant a track plays in that section. Changing a cell changes the song for that section; launching jumps to a section and loops it. This is not free clip launching: nothing is recorded and every track follows the same section."

**Settings (global `Settings`, frozen: get, set, open, on('change')).** Plus `off`, `close`, `defaults`, `attach(host)`, `apply()`. Keys and defaults:
`audio.sinkId` '' (default device), `audio.latencyHint` 'interactive', `audio.sampleRate` 0 (device rate), `export.bitDepth` 24, `export.sampleRate` 0 (engine rate), `export.tail` 2 (s), `view.default` 'last', `view.density` 'normal', `view.zoom` 100 (%), `view.meterDecay` 20 (dB/s), `view.peakHold` 1.5 (s; 0 off; -1 until clicked), `view.deviceOpen` 'panel'.
Storage: localStorage `hv.settings` (JSON, try/catch); in Electron also the app-data file `settings.json` through `HavantechnoShell.readAppData/writeAppData` (read once at load, the file wins; written on every change, debounced). The dialog is a modal with three tabs (Audio, View, About), arrow keys move between tabs, focus trapped and returned, Escape closes. Audio tab: output device select (`host.outputDevices()`; empty labels explained: the browser hides device names until a page has had microphone permission, so only "Default output" is offered by name), sample rate, latency hint, "Apply" through `host.setAudioOptions` (disabled with a reason when missing), the engine report from `host.audioOptions()` (falls back to `host.context()` for sample rate, base and output latency and state; worklet engine from `Worklets.ready(ctx)`), test tone (`host.testTone` if V1 adds one, else a 1 kHz sine at -18 dBFS for 1 s on the Host's own context: a read of `host.context()`, the only place the UI touches the context, for this diagnostic), export defaults. View tab: default view, density, zoom (80..150 %), meter decay, peak hold, device windows open on panel or controls. About: version (`HavantechnoShell.appVersion()` when present, else app/package.json's version read over fetch, else "web build"), the licence (AGPL-3.0-or-later), links to LICENSE and THIRD_PARTY.md.
Density and zoom: `html[data-density]` (compact, normal, large) changes control heights and padding in the toolbar, mixer, clips and dialogs (views.css); zoom is CSS `zoom` on `<html>` (Chromium and Electron support it; the toolbar wraps, so at 1280 px and 150 % nothing is cut off; checked in the browser). Device windows: Windows keeps the view per device in `hv.win.<id>`; app.js wraps `Windows.open` so that, when the setting is 'controls' and no view was chosen for that device before, the window opens on Controls. A cleaner hook belongs in windows.js (not my file): **To the coordinator / W1:** a `Settings.get('view.deviceOpen')` read in windows.js where it picks the first view would replace the wrapper.

**Export dialog (`ExportDialog.open(host, {shell, toast})`).** What: mix, stems for all tracks, or chosen tracks (checkbox list). Span: whole song, a section (select), bars from..to (1-based in the UI, 0-based `{from, to}` to the Host, `to` exclusive). Bit depth 16/24/32 float, sample rate (engine, 44100, 48000, 88200, 96000), tail seconds, "master chain on stems" checkbox (disabled for the mix). Defaults from Settings `export.*`. Run: `Project.exportAudio({host, shell, ...})` when present (it writes the files), else `host.exportAudio({...})` then each file saved through `shell.saveFile` (Electron) or downloaded (web). Progress: `onProgress` stages shown in a progress bar with a status line; Cancel aborts through an AbortController passed as `signal` (V1 may or may not honour it: the dialog stops waiting and discards the result either way, and says so). Result: a list of file names with seconds and peak (dBFS). When `host.exportAudio` is missing the dialog is not shown: the toolbar button falls back to the old 16-bit whole-song path (`App.exportWav`).

**Import audio.** A toolbar "Audio…" entry beside Import… (renamed nothing): `Project.pickFiles({multiple: true, accept: 'audio/*'})` or `Project.pickAudio` for one, then `host.addAudioTrack(file, {bar: pos().bar})` for each, sequentially; disabled with a reason when `host.addAudioTrack` is missing. The "+ track" menu in system-editor.js is not touched. **To the coordinator:** an "Audio track…" entry in the System Editor's "+ track" menu would need A4's file; not asked for here.

**Toolbar.** The view segment gains Mixer (enabled) and Clips. The Export WAV button becomes "Export…" (same place; falls back as above). New buttons: "Audio…" (import audio), and a Settings button (gear text "Settings", Ctrl/Cmd+,). The bar already wraps as a unit on the right.
