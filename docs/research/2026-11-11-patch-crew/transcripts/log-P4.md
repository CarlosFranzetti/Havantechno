## Design decisions

1. **One SVG per panel, controls inside it.** The whole panel is one `<svg viewBox>` with `preserveAspectRatio="xMidYMid meet"`, so it scales with the window and keeps its aspect; each control is an SVG `<g>` with `role="slider"`, `tabindex="0"`, `aria-valuenow/min/max/valuetext`. Reason: one coordinate system means columns can never drift off their knobs at any size, and nothing needs relayout code. No fonts beyond the page's system-ui stack, no images.
2. **Controls behave like Widgets** (same constants: 200 px for the full range, Shift x0.1, arrows 1 % of the range, PageUp/Down 10 %, Home/End, wheel only on the focused control, double-click home = the section's `set` value, else the song document's value at build time, else spec.value). One `host.hold(path)` per gesture, at its first value change; then `host.setParam`. A value readout (SVG callout) shows while adjusting and while focused.
3. **Hardware knobs in the columns, engine extras under the instrument selector.** Each voice column carries the knobs the hardware has (808: level/tone/decay, level/tone/snappy, level/tuning, level; 909: tune/level/attack/decay and so on), bound to the spec param of the same meaning. The engine has more params per voice than the hardware (drive, shift, burst spacing...; up to 8 extra for the claps); putting them all in the columns would crush the layout. They sit as small screwdriver trimmers in one "VOICE TRIM" strip that follows the instrument selector, like the internal trim pots of the real machine. Every spec param stays reachable on the panel, and the Editor tab keeps the full face.
4. **Voice binding.** A voice type binds to the first instrument device (host.devices(), refreshed on the host's 'document' event) whose type is that voice; its knobs write `<pathPrefix>.<param>`. A voice with no track is drawn dimmed with a "+" add button: `ed.group(ed.addTrack({name, type, inst, family:'drums', gain:0.8, variants:{A:'................'}}))` then `host.commit()`, as the kit menu does.
5. **808 paired voices** (LT/LC, MT/MC, HT/HC, RS/CL, CP/MA): the column's slide switch picks which voice the column shows (panel view state, not a param), as the hardware switch picks the sound.
6. **Accent**: the 808 AC and 909 total-accent knobs have no engine parameter (accent ratios are fixed in drums.js), so they are not drawn as knobs; the AC column says "Shift-click a step". No fake controls.
7. **Step keys**: the sixteen keys show the selected voice's cells in the section being viewed or played (host.transport.pos(): section, bar in section mod the variant's bars), as the System Editor does. Click toggles (`{vel:0.85}` / null), Shift-click accent (`{acc:true, vel:1}` / `{acc:null, vel:0.85}`); each edit is one `ed.group` (setPlay first when the section does not play the track) + `host.commit()`. LED lit = step on; a second small LED above = accent; the running light is a ring on the current step while playing.
8. **Bridge (Electron child windows)**: the bridge host has no `document`, `editor`, `commit` or transport play/stop. The panel feature-detects: knobs work everywhere; step keys, add and start/stop are drawn disabled when the host lacks them. **To coordinator / A6:** to make them work in child windows, makeBridge in app.js would need `document`, `editor`, `commit`, `transportPlay/Stop/Toggle`, and bootDevice would forward them (`h.document`, `h.editor`, `h.commit`, `h.transport.toggle`). Not done here (app.js is not my file).
9. **Windows hook** (windows.js, documented in the file header): a "Panel" button first in the view segment, shown only when `root.Panels && Panels.for(device, host)`; view 'panel' renders `Panels.render(device, host)`; a device with a panel opens on the Panel view unless the owner chose another view for it; without panels.js nothing changes.
